### `WP-057` — расчёт S21 совпадает с листами Mathcad HD35-M и HD35-L (#12 п. 1, `BUG-023`)

Результат: на параметрах листов HD35-M и HD35-L программа по умолчанию даёт кривую Фёдора (= Mathcad до 7–8 знака), а это закреплено регрессионными тестами.

Разбор письма Фёдора (проверено 18.11.2026):

- Архив Фёдора — снимок нашего `main` на Release 009 (`a22c0aa`); `smcapp/` он не менял. Правки только в legacy `backend/` и в двух новых ноутбуках `backend/Checking_HD35-M.ipynb`, `Checking_HD35-L.ipynb`.
- Его три правки исходников и их состояние у нас:
  1. `Radial_stub.py`: `dR = 2 → 1 µm` и `arange(…, Rmax + 1e-8 − 1e-6, …)` (не теряется последний срез) — в `smcapp/api/radial_stub.py` уже так (`WP-046`, D5): `N = round(Rmax/ΔRAD)` срезов, ширина `Rmin + ΔRAD·(r−1)·θ`.
  2. `in_output.py`: индексирование в `writer` — косметика, результат тот же; наш `IOService.write` идёт через `zip`, менять нечего.
  3. `Mex4(f0) → Mex4(f)` — у нас уже на частоте свипа (`WP-046`, D2). В его архиве `backend/main.py` при этом остался с `f0`; исправлено только в ноутбуках.
  - Ещё одна незаявленная правка: `Impedance.py` — `interp1d(…, kind='linear', assume_sorted=True)`; это значения по умолчанию, на число не влияет.
- Правки Mathcad (ceil→round в трансформаторах, `t_prox → 0`, разбиение интегралов, ε_eff двухпроводной линии DC-block) подгоняли лист к Python, коду они ничего не добавляют. Отдельно:
  - `Nstep_tr = round(|W2 − W1| / LW)` в листе; у нас число срезов — как у `arange` (`ceil((ΔW + 0.01 µm)/dw)`). При целом `ΔW/dw` (автоподбор только такие и выдаёт) совпадает; расхождение возможно лишь у трансформатора из файла с дробным `ΔW/dw`.
  - `t_prox = 0` → `C_prox = 0`: `D7` для совпадения больше не нужен; ёмкость анодного кольца переносится в backlog (`BL-007`).
- Сверка числом: наш `S21CalculatorImpl` на входах ноутбуков (сценарий `docs/screenshots/WP-057/compare_fedor.py`, 100–925 GHz шаг 5) против `S21_HD35-M-dB.tab` / `S21_HD35-L-dB.tab` Фёдора:

  | Δ(T) | Сетка σ | HD35-M max / rms, dB | HD35-L max / rms, dB |
  |---|---|---|---|
  | BCS-tanh, как в листе | 30–935, шаг 5 GHz, как в ноутбуке | 8.6e-7 / 2.2e-7 | 3.6e-10 / 4.0e-11 |
  | BCS-tanh | наша по умолчанию 20–1090, шаг 20 | 0.048 / 0.009 | 0.122 / 0.016 |
  | strong coupling (наш сейчас) | шаг 5 | 0.87 / 0.24 | 1.57 / 0.35 |
  | strong coupling | шаг 20 | 0.88 / 0.25 | 1.49 / 0.35 |

  Вывод: формулы цепи у нас уже совпадают с эталоном. Отличаются только модель Δ(T) (`D4`, до 1.6 dB) и шаг сетки σ (до 0.12 dB), плюс входы `D1`/`D3`.
- Входы листов: T = 4.4 K; EL1 (верхний, в листе электрод 2): Tc = 13 K, Δ0 = 1.835·kB·Tc (α = 3.67), σ = 0.975·10⁶, d = 0.5 µm; EL2: Tc = 9.5 K, Δ0 = 1.815·kB·Tc (α = 3.63), σ = 18·10⁶, d = 0.2 µm; h1 = 0.15, h2 = 0.25 µm, V_anod = 10 V, ε_i = 4.2, ε_Al = 9.8 → H12 = 0.415729 µm, E12 = 4.29281, H1 = 0.165729 µm, E1 = 4.44084; Z FFO = 0.25 Ω, RnS = 30 Ω·µm², C0 = 85 fF/µm², S = 1.0 (M) / 1.2 (L) µm². Геометрия M и L — в ноутбуках и в сценарии сравнения.

План работ:

1. Δ(T) по формуле листа `Δ0·tanh(1.74·√(Tc/T − 1))` (`delta_bcs_approx`, уже есть в `smcapp/api/superconductivity.py`) вместо strong coupling — решение владельца 18.11.2026: заменить, без выбора модели. Строка лога расчёта и `docs/calculation-model.md` — по новой модели.
2. Сетка σ по умолчанию — шаг 5 GHz (начало ≤ начала свипа, конец > конца свипа). Проверить время расчёта на HD35-M по умолчанию (сейчас ≈ 5 с на кривую с шагом 5) и что старые файлы со своей сеткой открываются как прежде.
3. `D1`: H12/E12/H1/E1 считаются из слоёв, как в листе (решение владельца 18.11.2026):
   - В группе Dielectrics вместо четырёх полей — h1, h2 (µm), V_anod (V), ε_i, ε_Al; по умолчанию как в листах HD35-M/L (0.15, 0.25, 10, 4.2, 9.8). Коэффициент анодирования 1.47·1.07 nm/V — константа (как `HaAl` в листе). Под полями — подсказка с вычисленными H1, E1, H12, E12, как у трансформаторов.
   - Калькулятор получает H/E из одной функции домена; `S21Config` хранит слои, H12/E12/H1/E1 — вычисляемые свойства.
   - Старые файлы с прямыми H12/E12/H1/E1: восстановить `h1 = H1 − Ha`, `h2 = H12 − H1` при V_anod = 10, ε_i = 4.2, ε_Al = 9.8; если пересчитанные E1/E12 отличаются от записанных больше 1e-4 — сообщить при открытии (какие значения были и какие стали). Новый формат файла — с версией и тестом чтения старого.
   - Экспорт «Параметры HFSS» (`WP-058`) выводит и слои, и вычисленные H/E.
   - Тесты: числа ноутбука Фёдора (H12 = 0.415729 µm, E12 = 4.2928099, H1 = 0.165729 µm, E1 = 4.4408406), граничные h → 0, V_anod = 0, отказ при h ≤ 0 и ε ≤ 0, чтение старого файла с совпадающим и несовпадающим E.

   Как в источниках:
   - Листы HD35-M и HD35-L одинаково: `h1i = 0.15 µm`, `h2i = 0.25 µm`, `Ei = 4.2`, `Vanod = 10`, `Ha = HaAl = 1.47·1.07 nm·Vanod`, `Ea = EAl = 9.8` (в листе есть и `HaNb = 2.1·0.87 nm·V`, `ENb = 40`, но не используются); `H1 = h1i + Ha`, `H12 = h1i + h2i + Ha`, `E(Hi) = Ei·Ea·(Hi + Ha)/(Ei·Ha + Ea·Hi)`, `E1 = E(h1i)`, `E12 = E(h1i + h2i)`.
   - Фёдор: в ноутбуке HD35-L — та же формула из `h1`, `h2`, `V_anod`, `E_i`, `E_Al`; в ноутбуке HD35-M — уже посчитанные числа (`H12 = 0.415729 µm`, `E12 = 4.2928099`, `H1 = 0.165729 µm`, `E1 = 4.4408406`).

Результат: на панели инструментов рядом с «Буфер» есть меню «Экспорт» с единственным пунктом «Параметры HFSS…»; он сохраняет `.txt` с выбором имени и папки.

### `WP-064` — ток на правой оси как I² в логарифмической шкале с размахом в dB (#12 п. 3)

Результат: для тока и отношения токов декада правой оси соответствует 10 dB, а рядом с Y2 min/Y2 max видно, сколько dB занимает выбранный диапазон.

- Сейчас (`WP-055`) ток A/mA/µA и I/I_g рисуется на правой лог-оси как есть — декада тока = 20 dB по мощности, что неверно читается рядом с S21 (письмо владельца с `LgI_for_scaling.xlsx`: графики I и lgI на лог-оси отмечены как неверные, I² на лог-оси 1500–15000 — верный).
- Алгоритм владельца:
  1. ток (или отношение токов) возводится в квадрат;
  2. I² рисуется на правой оси в логарифмической шкале; подпись оси — «I², mA²», «I², µA²», «(I/I_g)²»; Y2 min/Y2 max — в единицах I²;
  3. рядом с Y2 min/Y2 max — размах в dB `10·lg(Y2 min / Y2 max)`: 1500…15000 → −10 dB, 150…15000 → −20 dB. Обновляется при вводе полей, зуме и панорамировании правой оси.
- **Открытые вопросы к владельцу — выяснить до реализации этих частей:**
  - ❓ Отрицательные и нулевые токи: при возведении в квадрат знак теряется. Предложение — точки с I ≤ 0 не показывать и сообщать их число в диалоге, как сейчас для ≤ 0. Альтернатива — показывать |I|². Не решено.
  - ❓ Величины «Log» (в файле уже lg I): предложение — рисовать 2·lg I = lg I² линейно (как график `lgI^2` в файле владельца, 3.2–4.2), размах — `10·(Y2 min − Y2 max)` dB. Альтернатива — оставить «Log» как есть (`WP-055`). Не решено.
  - Основная часть (I² на лог-оси, поля в единицах I², размах в dB) от этих ответов не зависит и может идти раньше.
- Подпись у курсора — значение I² и исходный I. Пересчёт единиц между кривыми тока (mA² ↔ µA²) — как в `WP-055`.
- Тесты: квадрат и единицы (mA → mA², mA → µA² = ×10⁶), размах dB на примерах владельца и после зума, отбрасывание I ≤ 0, «Log» → 2·lg, подписи осей; прежние тесты `WP-055` обновить по новым ожиданиям.
- Ручная проверка: колонки `I, mkA` и `lgI` из `LgI_for_scaling.xlsx` (выгрузить в текст): ось I², поля 1500 и 15000 → −10 dB, 150 → −20 dB; зум колесом по правой оси меняет dB; тёмная тема, экспорт PNG.
- Связь: размещение полей Y2 — `WP-060`; делать вместе или сразу после него.
