# Дефекты

Здесь находятся только подтверждённые открытые дефекты. Правила ведения описаны в [`AGENTS.md`](../AGENTS.md).

## Открытые

- `BUG-024` — импорт HFSS и Experiment неодинаково определяет единицы частоты и может молча сместить кривую в 1000 раз. Приоритет: высокий — неверное сравнение S21 с внешними данными без сообщения об ошибке. Статус: воспроизведено на загрузчиках, не исправлено; предложение решения — `BL-005`, связано с `BL-004`.
  - Окружение: macOS, текущий `smcapp` после `WP-040` и переименования пакета, Python через `uv`. Код: `smcapp/infrastructure/trace_files.py`, `TraceFileReader.load` и `HfssTabReader.load`; UI выбирает эти загрузчики в `smcapp/ui/app.py`.
  - Данные: файл владельца `~/Downloads/SMC & mcad - сравнение/HD35-H2.tab`, 200 строк без заголовка, частота 100–1095 GHz и S21 в dB. Файл является экспортом SMC, а не подтверждённым экспортом HFSS; дефект — молчаливое принятие неоднозначных единиц, а не неверный коэффициент перевода THz → GHz.
  - Точное воспроизведение на уровне загрузчиков:
    1. Прочитать этот файл через `TraceFileReader().load(path)` — загрузчик пункта Experiment.
    2. Прочитать тот же файл через `HfssTabReader().load(path)` — загрузчик пункта HFSS.
    3. Сравнить `frequencies`, число точек и `coefficients`.
  - Ожидается: общие правила определения единиц для обоих импортов; при отсутствии однозначной единицы программа запрашивает её у пользователя с вариантами выбора. После выбора GHz оба импорта получают 100–1095 GHz и одинаковые S21.
  - Фактически: Experiment получает 100–1095 GHz, HFSS — 100 000–1 095 000 GHz; все 200 значений S21 одинаковые. HFSS без распознанной единицы использует THz и умножает частоты на 1000. Experiment единицы заголовка вообще не учитывает и оставляет числа как GHz.
  - Дополнительные подтверждённые случаи: `Freq (GHz)` в HFSS не распознаётся и также вызывает ×1000; `Freq [GHz]` распознаётся правильно. Таблица с заголовком `Freq [THz]` и числами 0.1/0.2 через HFSS даёт правильные 100/200 GHz, а через Experiment — неправильные 0.1/0.2 GHz. Расширение файла не определяет единицы.
  - Источник предположения: [GitHub #11](https://github.com/atepart/SMC_app/issues/11) требует импорт HFSS `.tab` с заголовком и частотой в THz, а также отдельные стили HFSS/exp. Из этого не следует, что файл без единиц можно безопасно интерпретировать как THz. Разделение кривых следует сохранить, обработку единиц — унифицировать.
  - Доказательства: локальный `docs/screenshots/MATHCAD-HD35-H2/hfss-import-diagnosis.json` содержит результаты чтения реального файла и синтетических вариантов заголовка. Воспроизведены вызовы реальных загрузчиков; повторный GUI-сценарий для этого дефекта пока не выполнялся. Переключение подписи оси GHz/THz — отдельный механизм отображения и не причина ошибочных координат.
  - Решение по указанию владельца: общий механизм проверки единиц входных данных для HFSS/Experiment; если единица частоты отсутствует, не поддерживается или неоднозначна, запросить явный выбор, не угадывая по величине чисел или названию пункта меню. Подробный контракт и критерии проверки — `BL-005`. Реализация в текущую работу пока не взята.

- `BUG-023` — S21 не совпадает с эталонным листом Mathcad на одинаковых параметрах. Приоритет: высокий; расчёт — главный результат программы. Статус: причины найдены и подтверждены числом; исправление — `WP-046`. `D2` и `D5` исправлены (см. changelog, `WP-046`); `D1`, `D3`, `D4`, `D6` ждут решения владельца. После D2+D5 файл HD35-H2 как есть даёт max |Δ| = 11.83 dB, rms = 2.20 dB (было 8.54 / 2.28): D2 без D1 ухудшает максимум. С входами листа D1+D3 — 0.466 / 0.201 dB (было 5.535 / 1.319).
  - Окружение: `main` после `WP-040`, macOS, `uv`. Данные владельца — `HD35-H2.aocdesign`, `HD35-H2.tab` (кривая SMC), `HD35-H2.xmcd`, `ratio_log.txt` и `frequency.txt` (кривая Mathcad, 10–1510 GHz с шагом 10). Хранятся локально у разработчика, в репозиторий не добавлены.
  - Воспроизведение:
    1. Открыть `HD35-H2.aocdesign`.
    2. Запустить Run S21 (100–1095 GHz).
    3. Сравнить кривую с `ratio_log.txt` в общих частотах.
  - Ожидается: совпадение с листом Mathcad с точностью численного интегрирования (сотые dB).
  - Фактически: форма похожа, но экстремумы сдвинуты вверх на 10–40 GHz, около 230 GHz есть ложный пик, max |Δ| = 8.5 dB, rms = 2.3 dB. Например, на 600 GHz −9.90 против −7.28 dB.
  - Диагностика: локальный отчёт `docs/screenshots/MATHCAD-HD35-H2/report.md`, вместе со скриптами и копией каскада с флагами исправлений. Все пять правок вместе дают max |Δ| 0.039 dB и rms 0.011 dB на 100 общих частотах.
  - Причины по вкладу:
    - `D1` — вход: в файле `h12 = 0.4657 µm` и `ε12 = 4.28265`, это значения по умолчанию из legacy (`h2i = 0.30 µm`). В листе `h2i = 0.25 µm`, то есть `H12 = 0.415729 µm` и `ε12 = 4.29281`. Вклад до 10.6 dB, в основном за счёт H12.
    - `D2` — исправлено в `WP-046`. Код: линия Mex04 (элемент 14, часть L1/W1) считается на фиксированной `f0 = 650 GHz` вместо текущей частоты (`smcapp/infrastructure/s21_calculator.py`, строки 189–193). Во всех листах HD35 она на `f[u]`. Вклад до 5.5 dB.
    - `D3` — толщина полоска в χ/Kf1 по Yassin. Код берёт толщину EL1 («top»), лист — `d2`, верхний электрод. Владелец ввёл «электрод 1» Mathcad (нижний) в EL1. Перестановка EL1↔EL2 даёт ровно исправленный результат. Вклад до 1.6 dB.
    - `D4` — Δ(T): в коде итерация strong coupling, в листе `Δ0·tanh(1.74·√(Tc/T−1))`. Вклад до 0.6 dB.
    - `D5` — исправлено в `WP-046`. Радиальный шлейф: шаг 2 µm вместо `ΔRAD = 1 µm`, и при шаге 1 µm `arange(…, Rmax − 1 µm, …)` терял бы последний срез. Вклад до 0.4 dB.
    - `D6` — Mex01 в листе разбит с `LW = 4 µm`, `L = 0.4 µm`, а UI не даёт задать `dl < 0.5 µm`. Вклад около 0.1 dB.
    - Не требуют правки: интерполяция σ по сетке 20 GHz (≤ 0.012 dB) и мост DC block на `Esef[1]` (< 0.001 dB).
